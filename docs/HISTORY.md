# PlanWise — release history

Moved out of `PROJECT.md` (11.10.2026) to keep the anchor small; newest first.

Current version: 0.4.5 (0.4.5 — task form v3 (new task; card and template keep the same row): the quick row now holds «☆ Главное», the time picker itself (labelled «Время», presets inside), the day chip and «🔔» once a time is set, plus «⋯ Ещё» for the rare fields; typing «завтра в 15:00 позвонить маме» sets day and time (chips show it, the tokens are stripped from the title on save; picking a time by hand wins over the typed one). Reminder is on by default, 🔔 only opens its settings. ★ + time + reminder is now 1 tap + typing instead of 5 taps. No Rust/DB changes; no new i18n keys. Checked on Pixel 7 Pro (versionCode 4005): install over 0.4.4, form rows, typed «tomorrow at 15:00 call mom» → 15:00 / пт, 23 окт. / 🔔 chips, cancel without saving. Browser: save stores the clean title, 15:00 and the next day; «Ещё» lists the rare fields; edit card keeps time/🔔. Not checked on the phone: saving, edit card, template mode.)

Previous version: 0.4.4 (0.4.4 — lighter task form (new task, card, template): the sheet shows the title, a quick row «☆ Главное / + Время / ⋯ Ещё» and nothing else; «+ Уведомить» joins the quick row once a time is set; the other optional fields (category, repeat, duration, subtasks, etc.) open behind «⋯ Ещё» (progressive disclosure, no new i18n keys, no Rust/DB change). 0.4.3 — review fixes: the «usually done by here» line accounts for done tasks that moved into the «Done» group (it sat too low); the check-pop animation survives the card moving to that group (the flag lives in a module-level set, the card remounts); the first-step window ignores a double Enter/tap (no duplicate step). 0.4.2 — quieter Today and summaries: week and month share one «Done / Let go / Stuck» summary + category dots (`PeriodSummary`); done tasks of the day fold into a «Done (N)» group under the open ones; the archive button is hidden when the archive is empty; the add row sticks to the bottom of the Day list on a phone; a short check-pop animation when a task is marked done (off under reduced motion). 0.4.1 — «Закрыть день» easier: «Не сделано (N)» + «Всё на завтра», neutral «Отпустить», «Главное a/b»; a task at ↻3 opens the first-step window (a 5–15 min step goes to tomorrow, the original to «Позже») from «Закрыть день» and from a drag to a later day. 0.4.0 — «Главное дня»: ★ «Главное» (difficulty=3, no DB change) in the card and the row; focus block at the top of Today with «Главное сделано»; one-line status; dashed «usually done by here» load line; hint to star when the day has no ★; Settings toggle «Главное дня». Stage 0.4.0 of docs/reports/2026-10-20-focus-plan.md. 0.3.5 — new task row (round check in the category color, one-line meta, subtasks collapsed to a counter, long-press drag on touch) and new task card («When» chips, optional fields behind «+», Duplicate/Delete under ⋯, bottom sheet on phone). 0.3.4 — «Позже» collapsed by default; Settings: sticky tab strip without a gap, tabs in even rows, theme section without a card-in-card; the «Хвосты с прошлых дней» line opens «Закрыть день». 0.3.3 — Day view: «Сегодня сделано: N» under the heading and «Хвосты с прошлых дней: N» (open tasks of earlier days are not listed in the day column, only in «Закрыть день»). 0.3.2 — close-day fixes: the button returns to «Закрыть день» when a new open task appears after closing; «Всё на сегодня сделано» is hidden while overdue tasks are open. 0.3.1 — closing the day as a ritual: the «Закрыть день» dialog opens with what was done today (count + up to 5 titles), closing shows a toast and the button turns «✓ День закрыт», the button is hidden when there is nothing to close, the Day view says «Всё на сегодня сделано.» when nothing is open; subtask heading is lighter. 0.3.0 — task cycle rework (audit `docs/reports/2026-10-19-planwise-audit.md`): honest data (`done_at`/`dropped_at` owned by DB triggers, «отпустить» = closed without doing, `postpone_count` + ↻3 limit), «Закрыть день» dialog, month summary, quick-add line parsing, one list «Позже» for every task without a day, repeats (daily/weekly/monthly; next occurrence is spawned on close — in Rust, and in the Android widget toggle `WidgetData.spawnNextRepeat`), ⟳ badge on the card, subtasks read-only on the main screen, auto-archive/auto-done removed, widgets say «Позже». 0.2.5 — the Android morning digest arrives on time with the screen off: instead of one repeating Interval alarm (after its first fire the plugin re-armed it with a non-wakeup `setExact(RTC)` — in Doze the digest waited until the phone was picked up — and it carried the task list from arm time) every one of the next 14 days gets its own one-shot `At` alarm (`setExactAndAllowWhileIdle(RTC_WAKEUP)`, restored after reboot) with that day's list and its own id (`digest_id`; a shared id let arming tomorrow dismiss today's digest from the shade); the fingerprint now includes the hour and the language (changing the digest hour used to keep the old alarm); `notify-digest.json` keeps `armed_days` (legacy `armed_day` migrated). 0.2.4 — phone false taps: a scroll that starts on a subtask no longer opens its editor and the keyboard (editing starts on a tap within 10 px, not on `pointerdown`); on a touch screen (`pointer: coarse`) the task title is read-only and a tap on it opens the task card instead of the keyboard. 0.2.3 — audit 11.10 fixes (`docs/reports/2026-10-11-audit-plan.md`): the Android digest no longer arrives twice (an OS-alarm fire is recorded as `sent_day` when the target moves past the hour — `retarget_digest`); turning off both notification toggles cancels the armed alarms on Android; the desktop digest is deduped across relaunches (persisted `sent_day`); the digest text starts with the date (a stale repeating alarm is recognisable); marking a task done from the widget cancels its reminders (Rust writes `files/notify-tasks.json`, Kotlin cancels); auto-import is skipped while an export is pending (lost-edit race); the priority sort ranks a hard untimed task above easy timed ones; import stages attachment files as tmp + rename after commit (a failed import no longer deletes live files); `notify_minutes` clamped to 7 days; restore of a past-day task skips the overlap check; scheduler mutexes survive poisoning. Optimisations: auto-sync runs in Rust (`sync_export`/`sync_import` — no multi-MB JSON over IPC), non-default locales are lazy chunks (main JS 550 → 434 KB). 0.2.2 — Android digest CATCH-UP: the OS alarm is armed only for a day that ALREADY has tasks before its hour, and after the hour the target flips to tomorrow, so a day planned in the morning got NO digest at all («не вылезают»). Now every sync tick inside the +6 h window after the configured hour shows «План на сегодня» once for a day that had neither an armed alarm nor a show — `digest_catchup_due` (pure, unit-tested) + a persisted marker `notify-digest.json` (armed_day/sent_day; a separate file, because the UI rewrites prefs wholesale). Task row on touch: a tap must now be a CLEAN tap (movement >10 px = scroll, ignored — scrolling used to open inline text editing), and a clean tap on the row OPENS THE CARD (the ✎ target is only 20-24 px); desktop unchanged (click on empty row space = edit text). 0.2.1 — tasks «в течение дня» (time_minutes NULL) now REMIND: one morning ping on the task's day at the digest hour, but ONLY when the digest is OFF — with the digest on, it already announces them at the same minute (no double ping); the reminder query no longer filters `time_minutes IS NOT NULL` (`ReminderRow.2` → Option, `morning_of`); card UI: `Перенести/Дублировать/Удалить` moved to their own row — on narrow screens they no longer push «Сохранить» past the card edge; hint «напомним утром» for time-less tasks (`form.allDayHint`, i18n ×9; 3 new unit tests). 0.2.0 — 9-language localization (ru/en/es/de/fr/pt/zh/ja/ko) incl. localized notifications via the `set_app_lang` bridge. 0.1.18 — task duplication («Дублировать» → Rust `duplicate_task`, full copy with subtasks, reminders re-arm for the copy, generic-Reminder vs travel/prepare same-minute dedup). 0.1.17 — the Android digest became a REPEATING Interval OS alarm (survives process death and reboot; BOOT receiver restores it; failed `show()` aborts the store write); since 0.2.2 the catch-up makes the digest independent of that alarm chain. 0.1.15/0.1.16 — BACK minimizes the app (warm relaunch); digest re-arms on day-content fingerprint change. Releases in `Ready-made versions of applications/PlanWise`).
