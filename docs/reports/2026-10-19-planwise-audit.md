# PlanWise — аудит существующего приложения и план доработки (19.10.2026)

Метод: код (`src/`, `src-tauri/src/commands.rs`), веб-версия с тестовыми задачами — десктоп 1440×900 и
телефон 375×812, светлая и тёмная тема. Отвечает на вопросы: перебор ли прототип, почему «только неделя»,
как строить на том, что уже есть, и не угнетает ли дизайн.

## 1. Что есть и что делает (карта)

| Часть | Что делает | Оценка |
|---|---|---|
| **Неделя** (`WeekView` сеткой / `WeekViewVertical` списком, переключатель «сеткой») | 7 дней, задачи с галочкой, время, цвет-категория, drag-n-drop между днями, «+ добавить» на каждый день, кнопка-зона «следующая неделя» | Ядро, работает хорошо — основа |
| **День** (`DayView`) | Та же колонка дня из недели + боковая зона «завтра» для переноса | Своей задачи нет — дубль колонки недели |
| **Месяц** (`MonthView`) | Сетка 6×7, в ячейке — только цветные точки категорий; клик → день/неделя; список задач выбранного дня | Обзор есть, но по точкам ничего не понять |
| **Правая панель** (`RightPanel`, `SomedayColumn`, `MiniCalendar`) | Мини-календарь + группы «В течение недели / месяца / Когда-нибудь» (мягкий срок `dueEpochDay`) + Архив | Группы — это почти «Входящие», но всегда раскрыты и пустые |
| **Карточка задачи** (`TaskCard`, `AddTaskModal`, `SubtaskList`) | Название, время, длительность, приоритет (`difficulty`), категория, заметка, подзадачи, вложения, напоминания (в т.ч. «время выходить» с учётом дороги) | Богато; длительность и приоритет нигде не используются в расчётах |
| **Архив** (`ArchivePanel`, `archive_overdue`) | При запуске **молча** уносит невыполненные задачи старше вчера в архив + серая плашка | Главный источник «задачи исчезают» |
| **Авто-выполнение** (`autoDonePastTime`, по умолчанию **вкл**) | Время задачи в прошлом → сама «сделано» | Галочка перестаёт значить «я сделал» |
| **Поиск** (`SearchBar`, `SearchResults`) | Текст + категория + период + статус + сортировка | Работает |
| **Настройки** (`SettingsPanel`, 1773 строки) | Темы, масштаб, видимость элементов, уведомления, дайджест, синхронизация через папку, экспорт/импорт, шаблон | Много ручек вместо решений |
| **Rust** (31 команда) | CRUD задач/подзадач/категорий/вложений, перенос, архив, бэкап, синхронизация, уведомления, виджеты | Надёжная база, миграции V1–V14 |
| **Виджеты** | macOS WidgetKit; Android: День, Неделя, Следующая, Когда-нибудь, Счётчик, Быстрое добавление | Есть — новые механики должны их не сломать |

## 2. Прототип — перебор?

**Да, частично.** Цикл верный, но в прототипе на каждую задачу навешано три решения: вес H/M/S, вектор,
место на черте. Это ровно то, от чего концепция предостерегала («обязательные оценки, теги, приоритеты»).

| Механика прототипа | Решение | На чём в приложении |
|---|---|---|
| Закрыть день: завтра / неделя / когда-нибудь / разбить / отпустить | **Оставить** — сердце цикла | новый диалог на базе `.modal-dialog` |
| ↻3 — блок переноса, «разбить или отпустить» | **Оставить** | `move_task` + поле `postpone_count` |
| Статус «отпущено» | **Оставить** | миграция V15 |
| Хвосты прошлых дней разбираются, не исчезают | **Оставить** вместо авто-архива | `archive_overdue` → «хвосты» |
| Заметка дня | **Оставить** | таблица `days` |
| Входящие | **Оставить** | 4-я группа в правой панели (без даты и без срока) |
| Вес H/M/S, бюджет 9 очков, лимиты H2/M3 | **Убрать.** Вместо — одна мягкая черта «обычно ты закрываешь N» из истории, ноль ручных оценок | расчёт по `done_at` |
| Векторы виза/деньги/жизнь/опц. | **Убрать как отдельное поле** — это уже есть: **категории-цвета** (Работа/Личное/Спорт). Перекос считаем по ним | `colorSetId` |
| Радар векторов, отдельный экран «Обзор» | **Сжать** в 3–4 строки сводки недели (сделано / отпущено / застряло / по категориям) | шапка недели или месяца |
| Режим «Фокус», «За шторой» | **Отложить** — проверить после 2 недель жизни с циклом | — |

## 3. Почему «только неделя»

Не «только», а **неделя — главная поверхность**: тебе близок формат tweek, а планирование вперёд и
перенос между днями идут именно там. Но в приложении уже есть три вида, и им надо дать **разные задачи**:

- **Неделя** — планировать и делать (как сейчас + хвосты, ↻N, кнопка «Закрыть день» у сегодняшней колонки).
- **День → «Сегодня»** — единственный экран, где видна черта, заметка дня и закрытие дня. Сейчас это дубль
  колонки, поэтому и непонятно «зачем он».
- **Месяц** — обзор и дальние даты: названия задач в ячейках вместо точек, отметка закрытых дней, сводка
  месяца сверху.

## 4. Дизайн — угнетает или нет

**Вердикт: не угнетает по цвету** (спокойный slate, мягкий акцент, красного почти нет, тёмная тема читается).
**Угнетает плотностью и «техничностью»** — список выглядит как форма, а не как день.

| # | Что | Почему давит | Исправление |
|---|---|---|---|
| D1 | Названия задач были **моноширинным шрифтом** (textarea в Chromium/Android WebView без `font-family`) | «печатная машинка», холодно, отчётно | **Исправлено** в этом коммите: `textarea { font-family: inherit }` в `App.css` |
| D2 | «+ подзадача» и «в течение дня» под **каждой** задачей | высота ×2, шум, ощущение анкеты | показывать при наведении/фокусе; «в течение дня» не писать вовсе (это отсутствие времени) |
| D3 | Плашка «Перенесено в архив просроченных задач» при каждом запуске | напоминание о провале + задачи исчезли | уходит вместе с авто-архивом → карточка «Хвосты: N — разобрать» |
| D4 | Пустые группы раскрыты: «Пусто. Перетащите сюда…» ×2 | пустота, ощущение недоделанного | пустые свёрнуты в одну строку |
| D5 | Мини-календарь — треть экрана на десктопе | дублирует стрелки и «Месяц», крадёт место у дня | по умолчанию свёрнут; открывается из иконки календаря |
| D6 | Месяц — только точки | большая пустая сетка, не на что смотреть | 2–3 названия в ячейке + «+N» |
| D7 | Шестерёнка у каждого дня, вертикальная полоса «следующая неделя» на телефоне | лишние элементы, съедают ширину | шестерёнку — в меню дня; полосу — только на десктопе |
| D8 | Сделанное только зачёркнуто, итога нет | не видно движения | счётчик «сделано сегодня: N» в шапке дня; в сводке недели — список сделанного |

## 5. План — на существующей основе, снизу вверх

**Этап 0 — спокойный вид (без миграций, 1 сессия).** D2, D4, D5, D7. Проверка: скриншоты до/после,
высота недели на телефоне.

**Этап 1 — честные данные (Rust, миграция V15).**
- `autoDonePastTime` по умолчанию **выкл**.
- `status` open/done/dropped (+`done_at`), `postpone_count` (растёт в `move_task` при переносе с ≤сегодня
  на будущее), таблица `days` (`closed_at`, `note`).
- `archive_overdue` больше не прячет — хвосты остаются на своих днях.
- Тесты Rust: перенос, статус, миграция старых бэкапов (`is_done` → `status`).

**Этап 2 — цикл в интерфейсе.**
- «Сегодня» (бывший День): черта «обычно закрываешь N» (после 2 недель истории), заметка дня,
  кнопка «Закрыть день» → диалог разбора; ↻3 блокирует перенос.
- Неделя: хвосты прошлых дней приглушены с меткой; чип ↻N; «Закрыть день» у сегодняшней колонки.
- Правая панель: группа «Входящие» сверху.
- Месяц: названия в ячейках, сводка (сделано / отпущено / застряло / по категориям).
- Виджеты Android: проверить, что «отпущенные» не показываются как открытые.

**Этап 3.** Разбор строки ввода (дата/время), повторы, сокращение настроек.

После этапов 0–1 — неделя живого использования, потом этап 2.

## Не проверено

- macOS-приложение (WKWebView): моноширинный шрифт подтверждён в Chromium (браузер = Android WebView).
- Android на устройстве, виджеты.
