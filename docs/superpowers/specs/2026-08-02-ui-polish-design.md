# Дизайн: Полировка UI, настройки видимости, поиск и сортировка

Дата: 2026-08-02. Проект: daily-planner (Tauri v2 + React + Rust/SQLite).

## Контекст и цели

Комплексный аудит UI выявил дефекты наложений, схлопывания колонок, разнобой
иконок и токенов. Пользователь просит:

1. Устранить наложения во всех видах и вариантах интерфейса.
2. Унифицировать дизайн: единые иконки с отступами, единые токены, однородность.
3. Дать возможность скрывать элементы интерфейса в настройках (выборочно).
4. Исправить неделю-сетку: задачи должны быть читаемы и в маленьком окне, и в фулл-окне.
5. Улучшить поиск и выбор фильтров (категория, статус, период) + сортировку результатов.
6. Проверить функциональность: всё нажимается, всё видно, настройки взаимосвязаны.

Принятый подход: системный (B) — единый слой иконок, секция «Интерфейс» в
настройках, фиксы адаптива, унификация токенов, проверка в браузере после
каждого шага.

## 1. Единые SVG-иконки — `src/components/Icon.tsx`

- Инлайн-SVG, viewBox 24, `stroke="currentColor"`, размер 16×16 по умолчанию
  (`props.size`, px — фиксированный размер, т.к. масштабирование даёт zoom).
- Цвет: `currentColor`; кнопки-обёртки (.icon-btn) дают `--text-secondary`,
  hover → `--text-primary`/акцент (уже в .icon-btn).
- Набор иконок: `search`, `calendar`, `gear`, `chevronL`, `chevronR`, `close`,
  `check`, `plus`, `drag` (grips), `dots` (⋮), `clock`, `palette`, `grid`,
  `list`, `calendarHide`, `sun`, `moon`, `monitor`, `trash`, `sort`, `filter`.
- Замена в UI:
  - TopBar: ‹ › 🔍 📅 ⚙ → Icon.
  - TaskCard: ⠿ (ручка) → Icon(drag); ✕ → Icon(close); чип цвета — кружок
    (без иконки) + Icon(palette) в title-подсказке не нужен.
  - TimePicker: ⏰ → Icon(clock); presets — текст.
  - SubtaskRow: ⋮ → Icon(dots); ✕ → Icon(close).
  - WeekView Toolbar: «▥ сеткой» → Icon(grid)+«сеткой», «▤⊨» → Icon(calendarHide),
    «▤» (показать) → Icon(calendar).
  - SettingsPanel: ⚙️ заголовок → Icon(gear)+текст; ☀️🌙🖥️ → Icon(sun/moon/monitor);
    💾 → Icon(save); ✕ → Icon(close); «+ Добавить» → Icon(plus)+текст.
  - MonthView-модалка: чипы с цветом остаются кружками; ✕ «Без категории» — Icon(close).
  - SearchBar: ✕ → Icon(close).
- Все иконки оборачиваются в единую кнопку с отступами: кнопка .icon-btn
  (высота --control-h-sm, паддинги токенами, gap: var(--sp-2) внутри при
  наличии текста).

## 2. Настройки видимости — секция «Интерфейс»

### Store (`store.ts`)
- Новое поле `visibility: VisibilityState`:
  ```ts
  interface VisibilityState {
    navArrows: boolean;     // стрелки ‹ › в TopBar
    search: boolean;        // кнопка поиска 🔍
    datePicker: boolean;    // кнопка даты 📅 (заголовок-дата остаётся кликабельным)
    miniCalendar: boolean;  // правая панель календаря (DayView/WeekView)
    taskTime: boolean;      // бейдж времени в строке задачи
    subtasks: boolean;      // блок подзадач
    taskActions: boolean;   // кнопки «цвет» и «удалить» в строке
    rolloverBanner: boolean;// баннер «Перенесено N задач»
  }
  ```
- Все значения по умолчанию `true`. Setter: `setVisibility(key, value)`.
- Persist: добавить `visibility` в `partialize` (тот же localStorage `todo-settings`).
- Кнопка «Настройки» (⚙) НЕ скрывается: без неё нельзя вернуть элементы.

### SettingsPanel
- Новая секция «Интерфейс» (после «Задачи», перед «Категории»):
  - чекбоксы-строки (стиль `.oled-toggle`) для каждого элемента, с пояснением
    в hint: «Скрытые элементы можно вернуть здесь же».

### Применение
- `App.tsx`: TopBar получает флаги (не рендерить скрытые кнопки); баннер
  rollover рендерится только при `visibility.rolloverBanner && rolloverCount > 0`.
- `DayView`: панель MiniCalendar — только если `visibility.miniCalendar` и окно
  достаточно широкое (см. §3).
- `WeekView`: `showCalendar` (локальный) ограничивается `visibility.miniCalendar`:
  кнопка тулбара и панель не показываются, если выключено в настройках.
- `TaskCard`: `showTime` учитывает `visibility.taskTime`; SubtaskList — если
  `visibility.subtasks`; блок кнопок (цвет/удалить) — если `visibility.taskActions`.
- Поиск: если `visibility.search = false`, кнопка скрыта; открытый поиск при
  выключении настройки закрывается (эффект в App: если searchOpen && !visibility.search → закрыть).

## 3. Неделя-сетка: читаемые колонки (фикс схлопывания)

Проблемы (подтверждены в браузере):
- Прошедшие дни: `flex: 0 0 88px` → поле задачи 0px (текст не виден, не редактируется) — при ЛЮБОЙ ширине окна.
- При ~900px с правым календарём колонка «сегодня» сжимается до 4px, контент вылезает под календарь.

Фикс (`WeekView.tsx`):
- Убрать жёсткие ширины по весу дня. Всем колонкам `flex: 1 1 0` + `min-width`:
  - обычные дни: `min-width: 140px`;
  - сегодня: `flex: 1.3`, `min-width: 180px`;
  - прошлые дни: `max-width: 260px` (лёгкая иерархия сохраняется, но не ценой читаемости).
- Обёртки колонок: убрать `minWidth: 0` (схлопывание), оставить `minHeight: 0`.
- Горизонтальный скролл при нехватке места уже есть (`overflowX: auto`) —
  теперь он реально срабатывает вместо сжатия.
- Результат: фулл-окно 1400px → колонки ~140–190px, задачи читаемы;
  узкое окно → скролл вместо 4px-колонок.

## 4. DayView: адаптив правой панели

- Правая панель MiniCalendar (280px) скрывается автоматически при
  `matchMedia("(max-width: 700px)")` (как narrow в WeekView), и настройкой
  `visibility.miniCalendar`.
- Боковая зона «завтра ▶» (38px) остаётся (drop-зона для drag), но при

## 5. Поиск и фильтры — `SearchBar` + `SearchResults`

### SearchBar (3 ряда, компактно)
1. Ряд 1: инпут поиска (flex: 1) + кнопка закрытия (Icon(close)).
2. Ряд 2: фильтр категорий — чипы с цветом И названием (не анонимные кружки):
   - чип «Все» (текст, активен при color === null);
   - чипы категорий: цветной кружок + имя, активный подсвечен рамкой акцента;
   - скролл по горизонтали при переполнении (`overflowX: auto`), чтобы не ломать ряд.
3. Ряд 3: три сегмент-группы (текст-кнопки, стиль `.mode-btn` уменьшенный):
   - Период: Все / Сегодня / Просроченные / 7 дней / Этот месяц;
   - Статус: Все / Активные / Выполненные;
   - Сортировка: По дате (ближние) / По дате (дальние) / По алфавиту / По времени / По категории.

### SearchResults
- Фильтрация: текст (есть) + категория (есть) + период + статус.
- Период:
  - Все — без ограничений;
  - Сегодня — `isToday`;
  - Просроченные — `isPast` и не выполненные? Нет: «Просроченные» = дата < сегодня (любой статус);
  - 7 дней — [сегодня, сегодня+6];
  - Этот месяц — календарный месяц сегодня.
- Статус: все / `!isDone` / `isDone`.
- Сортировка (по выбору):
  - По дате: `date ASC`, затем `timeMinutes ASC` (null в конец);
  - По дате ↓: `date DESC`, затем `timeMinutes ASC`;
  - По алфавиту: `title.localeCompare(title, "ru")` (регистронезависимо);
  - По времени: задачи со временем первыми (по времени), потом без времени, внутри — дата;
  - По категории: по имени категории (без категории — в конец), внутри — дата.
- Пустое состояние: «Ничего не найдено» + предложение сбросить фильтры (кнопка «Сбросить фильтры»).

## 6. Сортировка задач в днях

- Оставляем текущий порядок (Rust: время ASC → sortOrder ASC) — он корректен.
- Убираем дублирующую фронтовую пересортировку, если она расходится с Rust:

## 7. Унификация токенов и стилей

- ViewSwitcher: `background: #EDE6D5` → `var(--bg-tertiary)`; кнопки: радиус
  `var(--radius-sm)`, активная — `var(--bg-secondary)` + лёгкая тень
  (`var(--shadow-sm)`); высота `--control-h-sm`. Тёмная тема перестаёт ломаться.
- Оверлеи (DatePickerModal, MonthView-модалка, promote-диалог, settings-overlay):
  единый фон `var(--overlay)` = `color-mix(in srgb, var(--text-primary) 25%, transparent)`
  (объявить в App.css `:root`), вместо 4 хардкод-rgba.
- DatePickerModal: `startOfWeek(first, mondayFirst)` из стора (сейчас всегда Пн —
  баг взаимосвязи); px-размеры (260px, 13px, 9px, padding 16) → токены
  (--fs-*, --sp-*, --radius-*).
- MiniCalendar (не-large): px (9/10/11px) → токены (--fs-2xs/--fs-xs, --sp-*).
- Заголовки дней: единый формат «Пн, 27» в сетке (DayColumn) и вертикальной
  неделе (WeekViewVertical): `weekday short + ", " + число`, сегодня — акцент + ●.
  В DayView остаётся полный заголовок «Воскресенье, 2 августа».
- chip-btn: один канонический размер (20×20) для иконок; текстовые чипы
  (SearchBar «Все», категории с именами) — отдельный класс `.text-chip` —
  убрать inline-переопределения размеров.
- WeekShiftZone/SideDayZone: единые отступы (margin: var(--sp-2)) и
  вертикальный текст — выровнять глифы стрелок («◀ прошлая неделя» / «следующая неделя ▶»).

## 9. Браузерный фоллбек API (тестовая среда)

Проблема: приложение работает только под Tauri (фронт зовёт Rust через
`invoke`). В браузере (vite dev) без рантайма `window.__TAURI_INTERNALS__`
все команды падают — «добавление задач не работает» (ожидаемо, но мешает
тестировать UI без сборки Rust).

Фикс: `api.ts` — детект доступности Tauri:
- если `window.__TAURI_INTERNALS__` есть → реальный invoke (как сейчас);
- иначе → модуль `api-browser-fallback.ts`: полноценная реализация тех же
  команд на localStorage (tasks/colorSets/subtasks, те же сигнатуры, id через
  crypto.randomUUID, сортировка как в Rust: время ASC → sortOrder ASC).
- Уровень: dev-удобство; в проде (Tauri) код фоллбека не исполняется.

Проверка: добавить/удалить/перенести задачу, подзадачи, категории, поиск —
всё работает в обычном браузере на localhost:1430.

## 10. Экспорт/импорт данных (бэкап)

### Rust (`src-tauri`)
- Новая зависимость: `tauri-plugin-dialog = "2"` (+ регистрация в `lib.rs`).
- Команда `export_to(path: String) -> Result<(), String>`: читает ВСЕ
  color_sets, tasks, subtasks, сериализует в JSON:
  `{ "version": 1, "exportedAt": <ms>, "colorSets": [...], "tasks": [...], "subtasks": [...] }`
  и пишет файл по пути (перезаписывает).
- Команда `import_from(path: String) -> Result<usize, String>`: читает JSON,
  валидирует (`version`, массивы; невалидные записи пропускаются), в
  транзакции ЗАМЕНЯЕТ все таблицы импортированными данными, возвращает число
  импортированных задач.

### Фронт (`SettingsPanel`)
- Новая секция «Данные» (в конце списка):
  - «Экспорт…» — `dialog.save` (defaultName `daily-planner-backup-YYYY-MM-DD.json`)
    → путь в `export_to`.
  - «Импорт…» — `dialog.open` (json) → путь в `import_from` → перезагрузка
    задач/категорий; перед импортом confirm-диалог: «Данные будут заменены
    данными из файла. Продолжить?».
  - Ошибки показываются текстом в секции (не alert).
- npm-зависимость: `@tauri-apps/plugin-dialog`.
