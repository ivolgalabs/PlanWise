# Заметки к задаче (notes) — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить каждой задаче раскрывающуюся панель с текстовой заметкой (plain text), сохраняемую по blur, с настройкой видимости.

**Architecture:** Одна колонка `notes TEXT NOT NULL DEFAULT ''` в `tasks` (миграция V4 через refinery). Поле прокидывается через модель `Task` в команды `get_tasks`/`upsert_task` и в экспорт/импорт (версия бэкапа остаётся 1, поле опционально при импорте). На фронте — кнопка-иконка `note` в строке задачи (рядом с TimePicker), раскрывающая textarea под строкой; сохранение через существующий `api.upsertTask`. Настройка `visibility.notes` в «Интерфейс» скрывает кнопку и панель.

**Tech Stack:** Tauri v2, rusqlite 0.32 + refinery 0.8, React 19 + TypeScript, zustand (persist), Vite.

## Global Constraints

- Версия JSON-бэкапа в `export_to`/`import_from` **остаётся `1`** — старые файлы без `notes` импортируются как раньше.
- Сборка Rust — только через общий target (`~/.cargo-shared-target`): локальных `target/` в проекте не создавать; не запускать параллельные сборки других проектов.
- Браузерный фоллбек (`api-browser-fallback.ts`) должен оставаться синхронным по полям с Rust-командами.
- Комментарии в коде — на русском, в стиле окружающего кода.
- Коммиты — только после явного разрешения пользователя (правило AGENTS.md).

use rusqlite::Connection;
use std::sync::Mutex;
use tauri::{AppHandle, Manager};

/// Состояние БД, доступное Tauri-командам через State<Db>.
pub struct Db(pub Mutex<Connection>);

use refinery::embed_migrations;
embed_migrations!("migrations");

/// Открывает SQLite по пути и прогоняет миграции (refinery).
/// Вынесено из init, чтобы тесты могли открывать in-memory БД.
pub fn open(path: impl AsRef<std::path::Path>) -> Connection {
    let mut conn = Connection::open(path).expect("failed to open sqlite db");

    // Включаем WAL для лучшей конкурентности и быстродействия.
    conn.pragma_update(None, "journal_mode", "WAL").ok();

    migrations::runner()
        .run(&mut conn)
        .expect("failed to run migrations");

    conn
}

/// Инициализирует SQLite в app_data_dir и прогоняет миграции (refinery).
pub fn init(app: &AppHandle) -> Mutex<Connection> {
    let app_dir = app
        .path()
        .app_data_dir()
        .expect("app data dir not resolvable");
    FsUtils::ensure_dir(&app_dir).ok();
    let db_path = app_dir.join("daily_planner.sqlite");
    Mutex::new(open(db_path))
}
